Support

Known issues.

Last updated: 2026-11-07 · Lastout 0.4.2

What doesn't work yet in the current release, what you see when you hit it, and what to do meanwhile. Each item here was reproduced by us. When a fix ships, the item goes; the changelog says what changed. Found something that isn't here? Write to support@lastout.dev.

Terminals and shells

tmux and screen: the shortcut can copy the wrong command

With the terminal window itself in front, ⌃⌥⌘C can copy a command from before tmux or screen started, or report only that tmux is running, and the notice looks like a normal copy. Meanwhile: press ⌃⌥⌘L and pick the command, run lo in the pane, or press ⌃⌥⌘C from another app (a browser, a chat window): those get the pane's latest command.

tmux sees Lastout's proxy as the pane's process

#{pane_current_command} and the default window name show lastout-shell, #{pane_current_path} stays where the tab was opened (so a split made with -c "#{pane_current_path}" opens there, not in your current directory), and plugins that read ps -t #{pane_tty} (vim-tmux-navigator) can't see your programs. Meanwhile: name windows yourself (tmux rename-window). There is no workaround for the directory and the plugins yet.

Warp, JetBrains IDE terminals and Emacs terminals aren't recorded

Nothing in the app says so yet: it keeps waiting for a first command. Meanwhile: use one of the recorded terminals: Ghostty, iTerm2, Terminal, kitty, WezTerm, Alacritty, and the terminals of VS Code, Cursor and Zed.

A command started with zsh -i -c, bash -i -c or fish -ic stops at a prompt

In a recorded terminal such a command doesn't run: a prompt appears instead, and nothing says why. Zed runs its tasks this way, so a Zed task leaves a prompt and no output (Zed's terminal panel itself is recorded). A fix is planned for the next release. Meanwhile: run the command yourself in the terminal panel. If you need Zed's tasks now, keep Lastout out of Zed's shells, for example in ~/.zshenv: [[ $ZED_TERM == true ]] && export LASTOUT_DISABLE=1 (Zed's terminals are then not recorded).

Aliases, functions and GPG_TTY set in ~/.zprofile don't reach the recorded shell

In a new tab, aliases and functions defined in ~/.zprofile are missing, logout says this is not a login shell, and ~/.zlogout doesn't run. If GPG_TTY is set there and your pinentry runs in the terminal (pinentry-tty, pinentry-curses), a signature fails and the passphrase you type can be echoed, run as a command and recorded, by Lastout and by the shell's history. A graphical pinentry doesn't go through the terminal. Meanwhile: move those lines to ~/.zshrc, and set export GPG_TTY=$TTY there. If a passphrase was recorded: lo forget, check ~/.zsh_history, and change it.

Terminal.app closes a tab with a running command without asking

Terminal sees Lastout's proxy as the tab's shell and can't see the programs inside it, so ⌘W on a tab that is running something closes it at once and the command is killed; it used to ask first. In iTerm2's "If there are jobs besides" mode, add your shell (zsh) to the list, or it asks every time. Meanwhile: look before ⌘W.

code . typed in VS Code's own terminal opens a window that isn't recorded

0.4.2 records editors started from a recorded terminal tab. A window opened from inside VS Code's or Cursor's own integrated terminal still isn't, since both sides are the same editor and the new one looks like a shell inside a recorded one; lo doctor in it says the shell only borrowed Lastout's environment. Meanwhile: open the editor from the Dock, Spotlight, or a terminal app.

Copies and redaction

Some ways of writing a password aren't recognized

Redaction knows formats, not every secret. Not caught today, among others: curl -u user:pass, mysql -p<password>, sshpass -p, docker login -p, Cookie headers, DB_PASS=; the privacy policy has the whole list. Meanwhile: look before you paste. Start a command with a space to keep it out of the recording; lo forget removes one already recorded.

Folder and git branch names aren't redacted

A token in a directory or branch name shows as typed in lo sessions and in a coding agent's list of terminals. Meanwhile: rename the branch or folder.

A long log's error in the middle can be left out of the copy

The default copy keeps the start, the errors it has room for, and the end. With long lines (over about 100 characters, as in JSON or Spring Boot logs) and the error far from the end, the error can be dropped while the footnote still says "head, errors and tail". Meanwhile: lo --mode errors finds it; lo --mode full copies everything.

The Running list can keep a command that already ended

When the recording process was killed, or the data folder was moved, while a command ran, its entry stays under Running in the menu and the picker. Meanwhile: open a new terminal tab: it cleans the entry up.

Coding agents (MCP)

wait_for_command times out while another terminal is busy

With something running in any other terminal, including the agent's own or a dev server, wait_for_command waits for its whole timeout and then says the command is still running, even when it finished seconds ago. Meanwhile: have the agent pass session to name the terminal you'll use; the finished output is readable with get_command_output right away.

Display

On an external display, the island, the copy notice and the picker stay on the built-in screen

In island mode on a Mac with a notch, the notice after a copy and the ⌃⌥⌘L picker appear on the MacBook's own screen even when you work on the external one; the copy itself is fine. Meanwhile: Settings → Appearance → Floating bubble (or Menu bar only): those follow the screen you are on.

Not tested by us yet

These may work; we haven't run them, so a report from you helps:

  • the app on an Intel Mac (only lo was run there, under Rosetta);
  • macOS 14, 15 and 26: our runs so far are on macOS 27;
  • lssh against a real remote host;
  • FileVault turned off, or automatic login, where the keychain holding the license may not be readable yet;
  • an external display with the lid closed, Stage Manager, full-screen Spaces.

当前版本还有哪些地方不对、碰到时你会看到什么、暂时怎么绕过。这里每一条都是我们自己复现过的。修好的会从这页删掉，更新日志里有改动记录。遇到这里没写的问题，请写信到 support@lastout.dev。

终端和 shell

tmux 和 screen：快捷键可能复制到错的命令

终端窗口本身在最前时，⌃⌥⌘C 可能复制到进 tmux 或 screen 之前的某条命令，或者只提示 tmux 正在运行，而提示看起来和正常复制一样。暂时：按 ⌃⌥⌘L 选命令、在窗格里运行 lo，或者从别的 App（浏览器、聊天窗口）按 ⌃⌥⌘C，这几种都拿得到窗格里最新的命令。

tmux 看到的窗格进程是 Lastout 的代理

#{pane_current_command} 和默认窗口名显示 lastout-shell，#{pane_current_path} 停在开标签页时的目录（用 -c "#{pane_current_path}" 分屏会开到那里，而不是你当前的目录），靠 ps -t #{pane_tty} 判断程序的插件（vim-tmux-navigator）看不到你的程序。暂时：窗口名自己起（tmux rename-window）。目录和插件这两项还没有绕过办法。

Warp、JetBrains IDE 和 Emacs 的内置终端不录制

App 里目前没有提示，只会一直等第一条命令。暂时：用会录制的终端：Ghostty、iTerm2、Terminal、kitty、WezTerm、Alacritty，以及 VS Code、Cursor、Zed 里的终端。

以 zsh -i -c、bash -i -c 或 fish -ic 启动的命令停在提示符

在录制中的终端里，这样启动的命令不执行，只出现一个提示符，也没有报错。Zed 的任务就是这样跑的，所以 Zed 任务只留下提示符、没有输出（Zed 的终端面板本身会录制）。下个版本修。暂时：在终端面板里自己敲这条命令。现在就要用 Zed 任务的话，让 Lastout 跳过 Zed 的 shell，比如在 ~/.zshenv 里加 [[ $ZED_TERM == true ]] && export LASTOUT_DISABLE=1（之后 Zed 里的终端不录制）。

写在 ~/.zprofile 里的别名、函数和 GPG_TTY 进不了录制中的 shell

新开标签页里，~/.zprofile 定义的别名和函数没有，logout 说这不是登录 shell，~/.zlogout 也不运行。如果 GPG_TTY 也写在那里、而且你的 pinentry 在终端里跑（pinentry-tty、pinentry-curses），签名会失败，输入的口令可能回显在屏幕上、被当成命令执行，并被 Lastout 和 shell 历史记下。图形界面的 pinentry 不经过终端。暂时：把这些行挪到 ~/.zshrc，并在那里写 export GPG_TTY=$TTY。口令已经被记下的话：lo forget，检查 ~/.zsh_history，然后换口令。

Terminal.app 关掉正在跑命令的标签页时不再问

Terminal 把 Lastout 的代理当成标签页的 shell，看不到里面跑的程序，所以对一个正在跑东西的标签页按 ⌘W 会直接关掉、命令被杀，以前会先问。iTerm2 选了「有任务才问」的话，要把你的 shell（zsh）加进名单，否则每次都问。暂时：按 ⌘W 前看一眼。

在 VS Code 自己的终端里敲 code .，开出的窗口不录制

0.4.2 已经会录制从录制中的终端标签页启动的编辑器。但从 VS Code 或 Cursor 自己的内置终端里开出的新窗口仍然不录：两边都是同一个编辑器，新窗口看起来像是录制中 shell 里面的又一层；在里面运行 lo doctor 会说这个 shell 只是借用了 Lastout 的环境。暂时：从 Dock、Spotlight 或终端 App 里打开编辑器。

复制和遮盖

有些密码写法认不出

遮盖认的是格式，不是所有密钥。目前认不出的常见几种：curl -u user:pass、mysql -p<密码>、sshpass -p、docker login -p、Cookie 头、DB_PASS=；完整清单在隐私政策里。暂时：贴出去之前看一眼。命令以空格开头就不会被记录；已经记下的用 lo forget 删。

目录名和 git 分支名不遮盖

目录或分支名里带着的 token，会按原样出现在 lo sessions 和编程 Agent 读到的终端列表里。暂时：把分支或目录改名。

长日志中段的错误可能没进复制

默认复制保留开头、预算之内放得下的错误、以及结尾。行很长（约 100 个字符以上，比如 JSON 或 Spring Boot 日志）而错误又离结尾很远时，错误可能被丢掉，脚注却仍写着「head, errors and tail」。暂时：lo --mode errors 能找到它；lo --mode full 复制全部。

「Running」里可能挂着已经结束的命令

命令运行期间录制进程被强杀、或者数据目录被挪走，这条命令会一直留在菜单和选择面板的 Running 里。暂时：开一个新的终端标签页，它会把这条清掉。

编程 Agent（MCP）

别的终端有东西在跑时，wait_for_command 会等到超时

只要任何别的终端有东西在跑，包括 Agent 自己所在的终端或一个 dev server，wait_for_command 就会等满超时时间，然后说命令还在运行，哪怕它几秒前就结束了。暂时：让 Agent 传 session 指定你要用的那个终端；结束的输出用 get_command_output 马上能读到。

显示

接外接显示器时，灵动岛、复制提示和选择面板留在内建屏幕上

有刘海的 Mac 用灵动岛模式时，复制后的提示和 ⌃⌥⌘L 的选择面板出现在 MacBook 自己的屏幕上，即使你在看外接屏；复制本身是正常的。暂时：设置 → 外观 → 全局浮窗（或「仅菜单栏」），这两种跟着你所在的屏幕走。

我们还没测过

这些可能是好的，只是我们没跑过；你的反馈会很有用：

  • Intel Mac 上的 App（那里只跑过 Rosetta 下的 lo）；
  • macOS 14、15 和 26：我们目前都在 macOS 27 上跑；
  • lssh 连真实的远程主机；
  • 关掉 FileVault 或开了自动登录的 Mac：保存授权的钥匙串可能还读不到；
  • 外接显示器加合盖、台前调度、全屏 Space。
