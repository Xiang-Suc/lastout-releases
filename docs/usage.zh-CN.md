# 使用指南

[English](usage.md) · 简体中文

Lastout 记下终端打印过的内容，不用选中文字，就能把上一条命令的输出整理好、复制出来贴给 LLM。本文介绍 macOS 菜单栏 App 和 `lo` 命令行；App 的「设置 → 使用指南」是它的精简版。

## 基本流程

1. **照常使用终端。** 运行 `lo setup` 之后（App 第一次打开时会提示你完成这一步），每个新开的终端都会被录制：每条命令、它的输出、在哪运行、怎么结束的。已经开着的终端，在里面运行一次 `exec zsh`（`exec bash`、`exec fish`、`exec nu`）后开始录制。
2. **复制。** 在任何 App 里按 ⌃⌥⌘C，或者在终端里输入 `lo`。得到的是前台终端的最新输出（前台是别的 App 时，取所有终端里最新的一条），顶部带着命令行，格式是 Markdown。很长的输出只保留开头、出错位置附近和结尾，密钥会被遮盖。
3. **粘贴。** Lastout 从不抢焦点，⌘V 会贴到你原本在输入的地方：和 LLM 的对话、issue、agent。
4. **更早的命令。** ⌃⌥⌘L 把每个终端显示成一张卡片，列出它最近的命令：按数字键复制该终端的最新输出，用方向键选命令，直接打字则搜索所有终端。

`lo` 本身，以及成功执行的 `clear` 或 `cd`，都不算作最新命令。全屏程序（`vim`、`less`、`htop`）复制的是它最后显示的那一屏。

## 快捷键

### 任何 App 中（App）

| 按键 | |
|---|---|
| ⌃⌥⌘C | 复制最新输出 |
| ⌃⌥⌘L | 选择命令：打开灵动岛、浮窗、侧边停靠或面板，列出所有终端 |

两个都可以在「设置 → 快捷键」里修改。它们是全局快捷键，会从其他 App 手里抢走这个组合键，请避开你常用 App 的快捷键。

### 展开终端时

| 按键 | |
|---|---|
| 1–9 | 复制该终端的最新输出（搜索框为空时） |
| 直接打字 | 搜索所有终端；最近的命令里找不到时，也会搜更早的命令 |
| ↑ ↓ ← → | 在命令、终端之间移动 |
| 单击 | 选中命令 |
| ↵、双击 | 复制选中的命令 |
| ⌘↵、⌘ 单击 | 标记多条，一起复制 |
| ⇥ | 智能、完整或只要错误 |
| esc | 关闭 |

### 终端提示符下

| 按键 | |
|---|---|
| ⌃G | 查找已保存的命令并放到命令行上，不会执行 |
| 打字、↑ ↓（⌃P ⌃N）、↵ | 在列表中：筛选、移动、放到命令行上 |
| ⌃U、esc | 在列表中：清空已输入的内容、取消 |
| `lo` 后按 ⇥ | 补全它的子命令和选项（启用了 `compinit` 的 zsh、bash、fish、nushell） |

默认是 ⌃G，除非你在 `lo setup` 询问时选了别的键；`lo setup --saved-key ctrl-o`（或 `none`、`default`）可以修改。macOS 自带的 `/bin/bash` 3.2 无法修改命令行，在那里 ⌃G 会改为复制该命令。

### 设置窗口中

⌘1–⌘8 切换到对应的设置页；焦点在侧边栏时，↑ ↓ 切换上一页、下一页。

## `lo` 命令

| 命令 | |
|---|---|
| `lo` | 复制当前终端的上一条命令及其输出 |
| `lo -2` | 再往前一条 |
| `lo --last 3` | 最近三条合成一次粘贴，按时间先后排列 |
| `lo --id 41 --id 42` | 指定的几条（编号见 `lo --list`） |
| `lo --global` | 所有终端里最新的一条命令 |
| `lo --running` | 另一个终端里仍在运行的命令到目前为止的输出，比如开发服务器或耗时很长的构建 |
| `lo --mode full` / `errors` | 完整输出，或只要错误附近的内容；默认是 `smart` |
| `lo --print` / `--plain` | 打印出来而不复制 / 只要纯文本，不带 Markdown |
| `lo --no-redact` | 不遮盖密钥 |
| `lo --list` | 列出最近的命令及其编号 |
| `lo search QUERY` | 按命令内容查找，或在最近 200 条里按输出查找 |
| `lo wait` | 等正在运行的命令结束，再打印出来 |
| `lo pause --for 30m` / `lo resume` | 暂停录制（所有终端，或加 `--here` 只暂停当前终端）；暂停期间什么都不存，连命令本身也不存 |
| `lo forget` | 彻底删除上一条命令（比如不小心打印了密钥）；也可以 `--id 42` 或 `--all` |
| `lo sessions` | 正在录制的终端 |
| `lo doctor` | 检查安装情况，从 rc 文件一直到录制的输出 |

`lo --help` 列出所有选项。复制通过 pbcopy、wl-copy 或 xclip/xsel 完成；在 ssh 会话或没有图形界面的机器上，通过终端本身（OSC 52）复制，在 tmux 和 GNU screen 里也可以。

## 已保存命令

终于跑通的那条命令，连同它是干什么用的，留到下次：

```console
$ kubectl -n staging logs deploy/api --since=1h | grep -i timeout
$ lo save "staging api timeouts, last hour (VPN first)"
```

- **找回来：** 在任何提示符下按 ⌃G，输入 `stag time`，按回车。命令会放到命令行上，光标在末尾；可以先修改，再自己按回车。命令不会自动执行。
- **改为复制：** `lo saved staging`。
- **保存更早的命令：** `lo save "备注" -2`，或 `--id 42`。
- **保存还没运行过的命令：** `lo save "备注" -- 'git log | head'`。
- **管理：** `lo saved --list`、`lo saved --edit ID`、`lo saved --rm ID`。

它们存在 `saved.toml` 里（`lo saved --path` 显示位置）：纯文本的 TOML，可以直接编辑，也可以放进 dotfiles。录制过期清理和 `lo forget` 都不会动它。再次保存同一条命令会更新它的备注；在当前所在仓库里保存的命令排在最前面。

## 录制与隐私

- 以空格开头的命令完全不保存，连命令本身也不存。
- 密钥类工具（`op`、`pass`、`aws configure`、`vault read`、`kubectl get secret` 等）只记命令行，从不记输出。
- `lo pause`（或「设置 → 录制 → 暂停」）停止录制；暂停期间什么都不存。
- 旧的录制会自动清理：每个终端 200 条、30 天、最多 500 MB。`lo forget --all`（或「设置 → 录制 → 抹掉…」）立即删除全部。

Lastout 记录什么、存在哪、什么会离开你的电脑：见[隐私](privacy.zh-CN.md)。

## 通过 ssh

没有额外设置时，一次 ssh 会话会被记成一条命令。想把远程的每条命令分开记录，并在本地用 `lo` 或 ⌃⌥⌘C 复制：

```bash
lo remote-install me@server      # 每台主机一次：复制 3 个 shell 脚本，不装二进制
lssh me@server                   # 代替 ssh 使用（ssh 的选项都能用）
```

`lo remote-install --uninstall me@server` 可以移除。只对你信任的主机使用 `lssh`：那台主机上的进程可以伪造你录制里的记录。

## 配置

`lo config --init` 会写一份带注释的 `~/.config/lastout/config.toml`（「设置 → 录制 → 编辑配置…」会打开它）。每个选项都在文件里有说明：默认的输出模式和长度、永远不记录的命令或想要保留输出的命令、要额外录制的终端 App、你自己要遮盖的密钥格式。

## 编码 agent

`lo mcp` 是一个 MCP 服务器，只读，密钥始终遮盖。「设置 → Agent → 复制配置」给出你所用客户端的配置片段。agent 可以列出你的终端和最近的命令、读取输出、跟踪仍在运行的命令、等待命令结束、搜索；它做的任何事都不能修改、删除或运行你终端里的东西。

## 出问题时

- **`lo doctor`** 从 rc 文件一直检查到录制的输出，并告诉你该怎么做。
- **某个终端没有被录制：** 它是在接入之前打开的。新开一个标签页，或在里面运行 `exec $SHELL`。
- **快捷键没反应：** 被其他 App 占用了。到「设置 → 快捷键」换一个。
- **报告问题：** 「设置 → 关于 → 导出诊断信息」会生成一个不含任何命令和输出的 zip。把它连同 `lo doctor` 的输出附到 [github.com/Xiang-Suc/lastout-releases](https://github.com/Xiang-Suc/lastout-releases/issues) 的 issue 里。
