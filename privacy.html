Privacy policy.

Last updated: 2026-10-26 · English is the binding version; 中文为译本，两者不一致时以英文版为准。

What Lastout records, where it keeps it, what can leave your machine and how to delete it. Every statement here is checked against the code, and names the command or setting that enforces it.

Lastout is made by Rocha Tech LLC, a company registered in New Jersey, United States ("we"). What you record never reaches us. What does is only what buying and activating a license needs, described under Buying a license; for that data we are responsible (the data controller). Questions and requests: support@lastout.dev.

What is recorded

In a terminal set up with lo setup (or by the app), for each command:

  • the command line as the shell saw it, the working directory and its git branch at the time, start and end time, exit status;
  • what the command printed to the terminal: the first 1 MB and the last 4 MB of raw output, compressed. That includes anything the terminal echoed while the command ran, such as text you typed at a prompt. Text typed at a no-echo prompt (a password) is not echoed, so it is not recorded;
  • per terminal session: the terminal program's name, the tty and the recorder's process id, so lo can tell which terminal is which.

Nothing else: no keystrokes outside a command, no screenshots, no file contents the command did not print, no information about other apps.

What is not recorded

  • A command starting with a space: not even its text (the row says (private)). This is the shell's own convention for "keep out of history".
  • While paused: lo pause (every terminal) or lo pause --here (this one), optionally --for 30m; lo resume ends it early. Nothing is stored, not even the command.
  • Commands that print secrets: for the built-in list (op, pass, gopass, bw, lpass, aws configure, aws sts, gcloud auth, az login, ssh-keygen, gpg --export-secret-keys, security find-*-password, vault read|kv get|login|token, kubectl get secret, kubectl config view, gh auth token, heroku auth:token, npm token, doppler secrets, openssl genrsa, openssl genpkey, age-keygen, wg genkey, and more in crates/lastout-core/src/config.rs) only the command line and exit status are kept, never the output. Add your own with record.ignore in the config file, or lift a built-in entry with record.allow.
  • Terminals you did not set up: recording only happens where the two marked blocks from lo setup are in the shell's rc file. lo setup --uninstall removes them everywhere.

Where it is kept

What Where
Recordings (SQLite index + compressed output files) macOS: ~/Library/Application Support/lastout/; Linux: $XDG_DATA_HOME/lastout/ (default ~/.local/share/lastout/); or $LASTOUT_HOME
Configuration ~/.config/lastout/config.toml ($XDG_CONFIG_HOME honoured), or $LASTOUT_CONFIG
App settings (shortcuts, notification threshold) ~/Library/Preferences/dev.lastout.app.plist

The data directory is created with mode 700 (only your user can read it); lo doctor checks that it still is. Retention is automatic: 200 commands per terminal, 30 days, 500 MB in total, after which the oldest go first.

Saved commands (lo save) are a separate, plain-text file you wrote: ~/.config/lastout/saved.toml (mode 0600), with how often each one was used in saved-usage.tsv in the data directory. Retention never deletes them and lo forget leaves them; the MCP server doesn't read them, and the app's diagnostics export only says how many there are. A secret you save in a command stays in that file as you typed it, and lo saved copies and prints a command as saved, without redaction.

What leaves your machine

Nothing you recorded, ever, on its own. The command-line tools have no network code. The menu bar app makes two kinds of connection: the update check, and activating a license (below). Once a day (and when you choose Check for Updates…) it fetches the release list at github.com/Xiang-Suc/lastout-releases/releases/latest/download/appcast.xml to see whether a newer version exists. That request carries no data about you or your machine beyond what any download does (Sparkle's system profiling is off), and an update is installed only after you agree, and only if its signature matches the key built into the app. No telemetry, no crash reports, no account. Output leaves the machine only when you, or a tool you run, ask for it:

  • Copying (lo, the menu bar shortcut, a notification's Copy button) puts the rendered output on the clipboard, after redaction. Over lssh, the clipboard is still the local one.
  • Printing (lo --print, lo --json) writes it to the terminal, after redaction.
  • Agents (lo mcp, the MCP server for Claude Code, Codex and others): read-only tools that return rendered output with redaction always on. There is no argument an agent can pass to turn it off, and nothing the server can write or delete.
  • Notifications show the command line and its exit status on your screen, through macOS's notification center, nowhere else.
  • Activation (a paid version): when you enter a license key, the app sends one request to Lastout's license server (the address is in the app's Info.plist as LastoutLicenseServer; it is a Cloudflare Worker run by Lastout, source in service/): the key, a SHA-256 hash of this Mac's hardware UUID (so a key can count the Macs it is used on; the UUID itself never leaves the Mac), and the app's version. The server answers with the name and email from the purchase and the day the purchase's year of updates ends, which the app keeps in your keychain. That is the only time it connects, except Deactivate on this Mac, which sends the key and the same hash once more to free the seat. Nothing about your recordings goes with either request, and the app never phones home afterwards. A build with no server configured refuses every key and sends nothing.
  • Diagnostics (Settings → About → Export Diagnostics…) writes a zip where you choose, for you to attach to a bug report; the app sends it nowhere. In it: versions, Lastout's settings, the screens' sizes, the lo doctor checks, how many terminals are recorded, Lastout's own log from the last day and its crash reports from the last 30 days. Your home folder shows as ~, your user name and computer name are replaced, and no command line, output or license key is in it.

Redaction

Applied to every copy, print and agent read, never to what is stored (so lo forget exists for a secret that was printed). Each match becomes a labelled marker such as [REDACTED:github-token], so an LLM still knows what was there. Rules: known token formats (GitHub, GitLab, AWS access keys, Google, Stripe, Slack tokens and webhooks, SendGrid, Twilio, Shopify, npm, PyPI, DigitalOcean, Hugging Face, JWTs, generic API keys), private key blocks, passwords in URLs, authenticator setup keys (otpauth:// links, a labelled Setup key:, and base32 keys printed in groups of four), Authorization headers and bearer tokens, --password-style flags, SECRET=value assignments. Your own formats go in redact.patterns (regexes) in the config file. lo --no-redact skips it for a copy you make yourself; nothing else can.

Remote hosts

lo remote-install host puts three small shell scripts and one marked block per rc file on the remote host, no binaries. With lssh host, each remote command's output travels through your own ssh connection to the recorder on your machine and is stored only there. The remote host keeps nothing.

Deleting

  • lo forget removes the previous command; lo forget --id 42 a specific one; lo forget --all everything. Each removes the rows, the output files and the bytes they occupied in the database file (which is vacuumed), so nothing is recoverable from free space.
  • lo setup --uninstall removes Lastout's blocks from every shell's rc files (and a login file it created). Open terminals keep running as they are; new ones are plain.
  • To remove every trace: the two directories in the table above, the app from /Applications, and lo and lastout-shell from ~/.local/bin. The Homebrew cask's zap does the same.
  • Saved commands: lo saved --rm ID, or delete the file (lo saved --path).

The menu bar app

It asks for one permission, notifications, when it starts; it works without them (the menu and shortcuts don't need them). "Open at login" is off until you turn it on in Settings. It needs no accessibility, screen recording or input monitoring permission. Its only network connections are the update check and license activation, both described above.

While you record or share your screen, its overlays (the island, the bubble, the side dock, the copy confirmations, the picker) are left out of what is captured: you still see them, screenshots, recordings and the people watching your screen don't. The island, the bubble and the side dock also step aside while a video app, Keynote, PowerPoint or a game fills the screen. To tell, Lastout looks at which apps have windows on screen and where (macOS lists that without any permission; window titles and contents are not read, and nothing is kept), and at the category an app gives itself. Full-screen browsers, editors and terminals keep the overlays, a video full screen in a browser too. Both are on by default and can be turned off in Settings → Appearance (to record a demo of Lastout, say).

记录什么

在用 lo setup（或 App）接入的终端里，对每条命令：

  • shell 看到的命令行、工作目录和当时的 git 分支、开始和结束时间、退出状态；
  • 命令打印到终端的内容：原始输出的前 1 MB 和后 4 MB，压缩存储。这包括命令运行期间终端回显的内容，比如你在提示符处输入的文字。不回显的提示（密码）不会被回显，所以不会被记录；
  • 每个终端会话：终端程序的名字、tty 和录制进程的 pid，让 lo 分得清哪个终端是哪个。

除此之外没有：命令之外的按键、截图、命令没打印出来的文件内容、其他 App 的信息，都不记录。

不记录什么

  • 以空格开头的命令：连命令文本都不存（那一行只显示 (private)）。这是 shell 自己「不进历史」的约定。
  • 暂停期间：lo pause（所有终端）或 lo pause --here（只这一个），可加 --for 30m；lo resume 提前结束。什么都不存，连命令都不存。
  • 会打印密钥的命令：内置列表（op、pass、gopass、bw、lpass、aws configure、aws sts、gcloud auth、az login、ssh-keygen、gpg --export-secret-keys、security find-*-password、vault read|kv get|login|token、kubectl get secret、kubectl config view、gh auth token、heroku auth:token、npm token、doppler secrets、openssl genrsa、openssl genpkey、age-keygen、wg genkey 等，完整列表在 crates/lastout-core/src/config.rs）只保留命令行和退出状态，从不保存输出。配置文件里 record.ignore 可以加自己的，record.allow 可以把内置条目放开。
  • 你没有接入的终端：只有 rc 文件里有 lo setup 写入的两段标记代码的 shell 才会被录制。lo setup --uninstall 从所有地方移除它们。

什么会离开你的电脑

你记录的内容，永远不会自己离开。命令行工具没有任何网络代码。菜单栏 App 只有两种连接：更新检查，以及激活授权（见下文）。每天一次（以及你点「检查更新…」时），它从 github.com/Xiang-Suc/lastout-releases/releases/latest/download/appcast.xml 取发布列表，看有没有新版本。这个请求不携带你或你机器的任何信息（Sparkle 的系统信息上报是关闭的），更新只在你同意后安装，且签名必须与 App 内置的公钥匹配。没有遥测、没有崩溃报告、没有账号。输出只在你或你运行的工具要求时才离开：

  • 复制（lo、菜单栏快捷键、通知上的「复制」按钮）把整理后的输出放到剪贴板，先遮盖密钥。通过 lssh 时，剪贴板仍是本地的。
  • 打印（lo --print、lo --json）把它写到终端，先遮盖密钥。
  • Agent（lo mcp，给 Claude Code、Codex 等用的 MCP 服务器）：只读的工具，返回整理后的输出，遮盖始终开启。Agent 没有任何参数能关掉它，服务器也不能写或删任何东西。
  • 通知在你的屏幕上显示命令行和退出状态，通过 macOS 通知中心，仅此而已。
  • 激活（付费版）：输入许可证密钥时，App 向 Lastout 的许可证服务器（地址写在 App 的 Info.plist 里的 LastoutLicenseServer；由 Lastout 运营的 Cloudflare Worker，源码在仓库的 service/）发送一次请求，内容是：密钥、这台 Mac 硬件 UUID 的 SHA-256 哈希（用来统计一个密钥用在几台 Mac 上；UUID 本身不会离开这台 Mac）、App 版本号。服务器返回购买时的姓名和邮箱，以及这次购买所含一年更新的截止日，App 存进你的钥匙串。此后 App 不再联网，唯一的例外是「在这台 Mac 上停用」：它再发送一次密钥和同一个哈希以释放座位。两次请求都不包含任何关于你记录的内容，App 之后也不会「回家报到」。没有配置服务器的构建拒绝一切密钥，也不发送任何东西。
  • 诊断信息（设置 → 关于 →「导出…」）把一个 zip 存到你选的位置，供你报告问题时附上；App 不会把它发到任何地方。里面有：版本、Lastout 的设置、屏幕尺寸、lo doctor 的检查结果、正在记录的终端数量、Lastout 自己最近一天的日志，以及最近 30 天的崩溃报告。主目录显示为 ~，用户名和电脑名会被替换，不含任何命令行、输出或许可证密钥。

遮盖

对每次复制、打印和 Agent 读取生效，从不改动存储的内容（所以才有 lo forget 处理打印过的密码）。每处匹配变成带标签的标记，例如 [REDACTED:github-token]，LLM 仍能知道那里原来是什么。规则：已知的 token 格式（GitHub、GitLab、AWS access key、Google、Stripe、Slack token 和 webhook、SendGrid、Twilio、Shopify、npm、PyPI、DigitalOcean、Hugging Face、JWT、通用 API key）、私钥块、URL 里的密码、两步验证的设置密钥（otpauth:// 链接、带 Setup key: 这类标签的密钥、四个一组打印的 base32 密钥）、Authorization 头和 bearer token、--password 这类参数、SECRET=value 赋值。你自己的格式写在配置的 redact.patterns（正则）。lo --no-redact 只对你自己做的复制跳过遮盖，别的途径都不行。

远程主机

lo remote-install host 在远程主机上放三个很小的 shell 脚本和每个 rc 文件一段标记代码，不装二进制。用 lssh host 时，远程每条命令的输出经由你自己的 ssh 连接传到你机器上的录制进程，只存在你这里。远程主机什么都不保留。

删除

  • lo forget 删上一条命令；lo forget --id 42 删指定的；lo forget --all 全删。每种都会删掉行、输出文件以及它们在数据库文件里占过的字节（会 vacuum），空闲空间里恢复不出来。
  • lo setup --uninstall 从所有 shell 的 rc 文件（以及它创建的登录文件）里移除 Lastout 的代码块。开着的终端照旧，新开的恢复原样。
  • 要清得一干二净：上表里的两个目录、/Applications 里的 App、~/.local/bin 里的 lo 和 lastout-shell。Homebrew cask 的 zap 做的是同样的事。
  • 已存命令：用 lo saved --rm ID 删单条，或者直接删掉文件（路径见 lo saved --path）。

菜单栏 App

它启动时申请一个权限：通知；不给也能用（菜单和快捷键不需要）。「登录时启动」默认关闭，要在设置里自己打开。它不需要辅助功能、屏幕录制或输入监控权限。它的网络连接只有上面说的更新检查和激活授权。

你录屏或共享屏幕时，它的浮层（灵动岛、全局浮窗、侧边停靠、复制提示、选择面板）不会被截进去：你自己照常能看到，截图、录屏和看你屏幕的人看不到。视频 App、Keynote、PowerPoint 或游戏占满屏幕时，灵动岛、全局浮窗和侧边停靠也会让开。为了判断这一点，Lastout 会看哪些 App 在屏幕上有窗口、窗口在哪（macOS 不需要任何权限就能列出这些；不读窗口标题和内容，什么也不保存），以及 App 自己声明的类别。全屏的浏览器、编辑器和终端照常显示浮层，浏览器里全屏播放视频也一样。这两项默认打开，可以在「设置 → 外观」里关掉，比如要录 Lastout 的演示时。

授权记录在授权存续期间一直保留，因为没有它就无法校验授权码。它存放在 Cloudflare；发授权码邮件时，你的邮箱经过 Resend。它们和 Paddle 一样，可能在你所在国家以外（包括美国）处理这些数据。数据库只有我们能读；App 和网站通过 HTTPS 连接授权服务器。

网站

lastout.dev 是一组由 GitHub Pages 托管的静态页面。网站自己不设 cookie，没有统计、追踪像素或广告。字体从 Google Fonts 加载。产品页会加载 Paddle 的结账脚本（Paddle.js），这样「Buy」才能在页面上打开 Paddle 的结账窗口；那个结账窗口属于 Paddle，适用 Paddle 的隐私政策和 cookie 政策。付款后，感谢页用地址里的交易号向授权服务器取你的授权码。

第三方

  • Paddle：销售授权、处理付款（见上）。
  • Cloudflare：运行授权服务器、它的数据库和管理后台。
  • Resend：发送带授权码的邮件。
  • GitHub：托管更新检查读取的发布，以及 lastout.dev 网站。
  • Google Fonts：提供网站的字体。

它们各自只接触经过自己的那部分，适用各自的隐私政策。此外没有：Lastout 不内嵌统计、崩溃上报或广告 SDK（Sparkle 更新框架是开源的，什么都不上报）。我们不出售你的数据，也不与其他任何人分享，法律要求的除外。

你的权利

Lastout 记录的内容留在你的 Mac 上，用上面的命令由你自己管理，我们看不到。对于我们保存的授权记录，写信到 support@lastout.dev 可以要一份副本、更正或删除。删除后，这个授权码不能再激活任何 Mac；已经激活的 Mac 照常可用，因为 App 不会再校验。Paddle 按税法要求保留自己的订单记录：可以直接找 Paddle，也可以找我们转达。视你所在地区（比如欧盟、英国或加州），法律可能还给你更多权利，比如提出反对，或向数据保护机构投诉。
